# Проектная память

Эти правила дополняют более узкие `AGENTS.md` в подкаталогах и не заменяют их.

## В начале каждой сессии

1. Прочитать `knowledge/INDEX.md`.
2. Прочитать `knowledge/CURRENT.md`.
3. Прочитать решения, на которые ссылается `CURRENT.md` и которые относятся к задаче.
4. Перед анализом структуры кода выполнить `graphify reflect --if-stale`, прочитать
   `graphify-out/reflections/LESSONS.md` и запросить существующий граф командой
   `graphify query "<вопрос>"`. Не заменять запрос повторным полным сканированием.

## В конце сессии

Если менялись файлы или принимались решения:

1. Создать `knowledge/sessions/YYYY-MM-DD-HHMM-topic.md` из
   `knowledge/templates/session.md`.
2. Записать результат, изменённые файлы и службы, проверки, решения, остаток,
   риски и способ отката.
3. Добавить внутренние wikilinks на спецификацию, связанные решения, прошлые сессии и
   [[graphify-out/GRAPH_REPORT|Graphify report]].
4. Обновить `knowledge/CURRENT.md`.
5. Долговременное решение оформить отдельной заметкой в `knowledge/decisions/`
   и добавить в `knowledge/INDEX.md`.
6. После изменений кода убедиться, что Graphify Git-hook обновил граф. Для
   документов достаточно записать необходимость семантического обновления;
   внешние LLM и платные API без разрешения не подключать.

Никогда не сохранять в проектной памяти пароли, токены, приватные ключи или
содержимое `.env`.
