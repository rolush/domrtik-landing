# Диагностика SMTP для opt.domtrik.ru

## Что сделано

- Подтверждено, что задача относится только к `opt.domtrik.ru`; основной сайт
  `www.domtrik.ru` не изменялся.
- Проверено, что публичный лендинг отправляет формы через `send.php`, а
  CMS-предпросмотр — через `/api/leads/submit`.
- Получателем production-формы установлен `rolush@yandex.ru`.
- Проверены текущий SMTP лендинга и SMTP-код основного сайта: оба соединения
  отклоняют авторизацию, письма не были приняты к доставке.
- В SMTP.BZ добавлен `domtrik.ru`; домен остаётся неактивным до DNS-верификации.
- Закрыта утечка закодированных данных авторизации в журнал SMTP-ошибок, ранее
  записанные значения обезличены.
- Публичная форма подключена к Яндекс SMTP через отдельный пароль приложения;
  контрольное письмо принято сервером.

## Изменённые файлы и службы

- Локально и на Beget: `send.php` — безопасное имя команды в сообщениях об
  ошибках SMTP.
- Beget: `/home/d/domtrik/opt.domtrik.ru/public_html/config.php` — получатель
  `rolush@yandex.ru`; секретные значения не зафиксированы в репозитории.
- Beget: `/home/d/domtrik/opt.domtrik.ru/public_html/send-error.log` — удалены
  закодированные данные авторизации.
- Beget: обезличенный отладочный журнал перемещён за пределы публичного
  каталога.
- SMTP.BZ: добавлен неактивный домен отправителя `domtrik.ru`.

## Проверки

- `send.php` и `config.php` прошли проверку синтаксиса PHP 8.3 на Beget.
- Оба маршрута формы отвечают и распознают поле-ловушку без создания заявки.
- Финальная отправка через Яндекс SMTP завершилась HTTP 200 и `ok: true`;
  единственный получатель — `rolush@yandex.ru`.
- Сообщений на `manager@domtrik.ru` и других посторонних адресатов не было.
- В отдельном журнале больше нет строк с закодированными AUTH-значениями.
- DNS проверен без изменений: зоной `domtrik.ru` управляет Cloudflare.
- Главная страница и `/admin/login` отвечают HTTP 200, старый публичный журнал
  отвечает HTTP 404.

## Решения

- Не переносить устаревшие SMTP-настройки основного сайта в лендинг.
- Принято [[knowledge/decisions/2026-09-14-yandex-smtp|решение использовать
  Яндекс SMTP для публичной формы]].
- Не добавлять ещё одну SPF-запись вслепую: у `domtrik.ru` уже опубликовано
  несколько конфликтующих SPF-записей.

## Остаток

- Проверить получение тестового письма в папках «Входящие» и «Спам».
- При необходимости отдельно подключить email-адаптер Payload для системных
  писем CMS.
- Удалить неиспользуемый неактивный домен из SMTP.BZ.

## Риски

- Некорректное добавление четвёртой SPF-записи ухудшит доставляемость почты
  основного домена; существующие SPF нужно объединять, а не дублировать.
- Старый почтовый код основного сайта хранит учётные данные в исходном файле;
  их следует отдельно заменить и вынести из публичного каталога.

## Откат

- Конфигурация лендинга: восстановить
  `/home/d/domtrik/opt.domtrik.ru/public_html/config.php` из резервной копии
  `config.php.before-yandex-20260914-2130` и отозвать пароль приложения.
- Код обработчика: восстановить
  `/home/d/domtrik/opt.domtrik.ru/send.php.before-smtp-security-20260914-2120`.
- Неактивный домен можно удалить в панели SMTP.BZ; DNS пока не изменялся.
